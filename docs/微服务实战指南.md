# 微服务实战指南

> 返回 [README](../README.md)。本文是「巧见 · AI 个性化手作平台」项目的完整实战文档，覆盖架构、微服务知识点索引、启动步骤与验证清单。

一个 **AI 驱动的个性化手作平台全栈微服务实战项目**：Spring Boot 3 + Spring Cloud 后端、Vue 3 双前端（C 端商城 + B 端后台），并以 Python **AI 助手**（LangGraph Agent + RAG + 文生图）为核心能力，为用户提供个性化推荐与导购。

> 面向微服务学习者：项目把「注册中心 → 网关 → 服务调用 → 熔断降级 → 担保交易 → 支付回调 → 实时 IM → LLM Agent」这条链路全部跑通，每个知识点都能在代码里找到落点（见 [知识点索引](#五微服务知识点索引)），而不是只做一个 CRUD Demo。

---

## 一、功能总览

**C 端商城（`web-ui`，`:5173`）**
- 注册 / 登录（账号密码 + 手机验证码）、商品浏览与搜索、商品详情
- 购物车、下单结算、**支付宝沙箱支付 + 余额充值**、订单列表与详情
- 在线客服 WebSocket 聊天、**AI 导购助手**（流式 SSE 对话、文生图）

**B 端后台（`admin-ui`，`:5174`）**
- 仪表盘统计、商品管理（含图片上传）、订单管理、用户管理
- 系统管理：管理员 / 角色 / 菜单权限、操作日志

**AI 助手（`ai-service`，`:8000`）**
- 意图路由 + 工具调用的多轮 Agent（LangGraph），RAG 检索增强
- 模型分级（路由/校验用小模型，生成用大模型）、答后校验、Token 与步数护栏
- 无 Key 时自动降级为 mock 模式，项目仍可跑通

## 五、微服务知识点索引

这一节是给学习者的地图：**每个知识点解决什么问题、在本项目哪段代码里体现**。

| 知识点 | 解决什么问题 | 代码落点 |
|---|---|---|
| **Nacos 服务注册与发现** | 服务 IP 漂移后不用改配置，按服务名互相寻址 | 各服务 `application.yml` 的 `spring.cloud.nacos.discovery`；本机固定注册 `ip: 127.0.0.1`，避免换网络后残留过期地址 |
| **Nacos 配置中心** | 配置集中管理 + 动态刷新，改配置不重启 | 各服务 `bootstrap.yml`，共享配置 `common-config.yaml`（`refresh: true`） |
| **Gateway 统一入口** | 前端只认一个域名，鉴权/跨域收口 | `gateway/application.yml` 的 `routes`（`lb://service-name` 走负载均衡）；**运行时以 Nacos `gateway.yaml` 为准**，本地 routes 会被覆盖 |
| **OpenFeign 远程调用** | 跨服务调用像调本地方法 | `order/feign/UserFeignClient.java`、`ProductFeignClient`、`AccountFeignClient` |
| **LoadBalancer 负载均衡** | 多实例自动分摊流量 | `lb://` 前缀 + `spring-cloud-loadbalancer` |
| **Resilience4j 熔断降级** | 下游挂了不拖垮上游，快速失败而非线程池打满 | `order-service/application.yml` 的 `resilience4j`；降级实现见 `order/feign/fallback/` |
| **统一响应 & 全局异常** | 前后端契约一致，异常不裸奔 | `common/result/R.java`、`common/exception/GlobalExceptionHandler.java` |
| **独立数据库** | 服务间数据隔离，边界清晰 | 一服务一库：`sql/schema.sql` 等 |
| **分布式锁 + 原子扣减** | 防库存超卖 | `product/service/impl/ProductServiceImpl#deductStock`：Redis 锁串行化 + SQL `stock >= quantity` 原子更新 |
| **担保交易状态机** | 钱先冻在平台，确认收货才打款给卖家 | `order/constant/OrderStatus.java`；`account` 的 `balance` / `frozenAmount` 分离 |
| **超时关单** | 未支付订单长期占用库存 | `order/task/OrderTimeoutCancelTask`（依赖 `OrderApplication` 上的 `@EnableScheduling`） |
| **幂等** | 支付回调重复到达不能重复入账 | `account/controller/AlipayCallbackController` |
| **AOP 审计日志** | 后台操作可追溯 | `admin/aspect/AdminOperationAspect` + `@AdminOperation` |

## 六、快速开始

### 1. 环境要求

| 依赖 | 版本 | 是否必须 |
|---|---|---|
| JDK | 17+ | 必须 |
| Maven | 3.8+ | 必须 |
| Node.js | 18+ | 前端必须 |
| Python | 3.10+ | AI 服务必须 |
| MySQL | 8.0+ | 必须 |
| Redis | 6+ | 必须 |
| Nacos | 2.x（standalone） | 必须 |
| RocketMQ | 5.x | 可选（不启动则聊天不做异步落库/群推） |
| Elasticsearch | 8.x | 可选（不启动则商品检索与 RAG 走降级逻辑） |

### 2. 初始化数据库

按顺序执行 `sql/` 下的脚本：

```bash
mysql -u root -p < sql/schema.sql                  # 用户/商品/订单/账户库
mysql -u root -p < sql/admin-schema.sql            # 后台管理库
mysql -u root -p < sql/chat-schema.sql             # 聊天会话库
mysql -u root -p < sql/alipay_recharge.sql         # 充值流水相关
mysql -u root -p < sql/insert-sample-products.sql  # 示例商品数据
mysql -u root -p < sql/kefu-account.sql            # 平台客服账号
```

> `update_from_entities.sql` 是实体变更后的增量 DDL 归档，新环境无需执行。

### 3. Nacos 准备（最容易踩的坑）

这一节没做完，后面所有服务都会"启动成功但互相找不到"，务必先做。

**① 命名空间不是 public**

所有服务统一注册到：

```
namespace: 4fbcf13a-853a-4f73-90d8-5569f59d827d
group:     DEFAULT_GROUP
```

在 Nacos 控制台新建命名空间，ID 填 `4fbcf13a-853a-4f73-90d8-5569f59d827d`（名称随意，如 `cloud-mall`）。

> 想用默认的 `public` 也可以：把各服务 `application.yml` 与 `bootstrap.yml` 中的 `namespace` 一行删掉即可。

**② 必须在 Nacos 建的配置**

配置模板都写在根目录的 `nacos-config.txt` 里，按注释拆分粘贴即可：

| Data ID | 是否必建 | 内容 |
|---|---|---|
| `common-config.yaml` | **必建** | 各服务 `bootstrap.yml` 通过 `shared-configs` 引用，含 MyBatis-Plus、数据源驱动、Resilience4j 公共参数。不建会启动失败 |
| `gateway.yaml` | **必建** | 网关路由。**运行时真正生效的路由来自这里**，本地 `gateway/application.yml` 会被覆盖——本地改路由不生效（实测 404） |
| `account-service.yaml` | 可选 | 支付宝沙箱参数；本地 `application.yml` 已配且不建此项时以本地为准 |
| `admin-service.yaml` | 可选 | admin-service 数据源等 |

两个高频踩坑点：

- 接入支付宝回调时，`gateway.yaml` 里必须额外加一条 `/alipay/**` → `lb://account-service` 的路由，否则回调 404。
- Nacos 改完路由**当前版本不热刷新**，需要重启网关。

### 4. 配置（**敏感信息一律环境变量，不入库**）

项目所有连接串、密钥均通过 Spring 占位符 `${XXX:默认值}` 读取环境变量，yml 中不含任何真实凭据。

**后端通用变量**

| 环境变量 | 说明 | 默认值 |
|---|---|---|
| `DB_URL` | JDBC 连接串 | `jdbc:mysql://127.0.0.1:3306/<库>?...` |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号密码 | `root` / 空 |
| `UPLOAD_DIR` | 后台图片落盘目录 | `./uploads` |
| `ADMIN_INIT_USERNAME` | 后台初始化管理员登录名 | `admin` |
| `ADMIN_INIT_PASSWORD` | 后台初始化管理员密码（**未设置则不自动建号**） | 空 |

**支付宝沙箱（account-service）**

| 环境变量 | 说明 |
|---|---|
| `ALIPAY_APP_ID` | 沙箱应用 APPID |
| `ALIPAY_MERCHANT_PRIVATE_KEY` | 应用私钥（请求签名） |
| `ALIPAY_PUBLIC_KEY` | 支付宝公钥（回调验签，**注意不是应用公钥**） |
| `ALIPAY_NOTIFY_URL` | 异步回调地址，需公网可达；本地开发可用内网穿透，隧道域名变更时同步修改 |
| `ALIPAY_RETURN_URL` / `ALIPAY_FRONTEND_URL` | 支付完成后的前端跳转地址 |
| `ALIPAY_GATEWAY_URL` | 沙箱网关地址 |

**AI 服务（ai-service）**

```bash
cd ai-service
python -m venv .venv && ./.venv/Scripts/activate     # Windows
pip install -r requirements.txt
cp .env.example .env                                  # 填写 LLM_API_KEY 等
```

沙箱配置参考：支付宝开放平台 → 沙箱应用。

### 5. 启动

```bash
# 0) 中间件：Nacos 单机模式（其余按需启动）
nacos/bin/startup.cmd -m standalone

# 1) 安装公共依赖到本地仓库（common 模块必须先装，否则业务服务找不到 R<T>）
mvn clean install -DskipTests

# 2) 先启动网关
cd gateway && mvn spring-boot:run

# 3) 再逐个启动业务服务（顺序不限）
mvn -pl user-service,product-service,order-service,account-service,admin-service,chat-service spring-boot:run

# 4) 前端
cd web-ui   && npm install && npm run dev     # :5173
cd admin-ui && npm install && npm run dev     # :5174

# 5) AI 服务
cd ai-service && python main.py               # :8000
```

启动后在 Nacos 控制台 `http://127.0.0.1:8848/nacos` 的服务列表中应能看到全部微服务。

## 七、动手验证清单

跑起来之后，按下面的顺序逐个"看见"知识点，比读代码印象深得多。

| 想验证的知识点 | 怎么验 |
|---|---|
| 服务注册与发现 | 打开 Nacos 控制台 → 服务管理 → 服务列表，看 6 个业务服务（user/product/order/account/admin/chat）是否在线 |
| 网关路由 + 负载均衡 | 直连 `http://localhost:8081/user/get/1` 与走网关 `http://localhost:8080/user/get/1`，两者结果一致即路由生效 |
| Feign 远程调用 | 调下单接口，观察 order-service 日志中出现对 user/product/account 的 Feign 调用 |
| **熔断降级** | 停掉 `product-service`，再调下单接口：不会 500 卡死，而是快速返回降级结果（见 `order/feign/fallback/`） |
| 库存防超卖 | 用 `jmeter/stock_deduct_test.jmx` 并发扣库存、`jmeter/order_create_test.jmx` 并发下单，观察库存不会出现负数 |
| 超时关单 | 造一张 PENDING 订单并把 `create_time` 改到 30 分钟前，等一个扫描周期看是否自动取消 |
| 配置动态刷新 | 在 Nacos 改 `common-config.yaml`，配合 `@RefreshScope` 的 Bean 无需重启即生效 |
| 统一响应格式 | 任意接口返回均为 `{code, message, data, timestamp}`，见 `common/result/R.java` |

> 学习建议：先只启动 `user-service` + `gateway` 跑通单服务，再逐步加服务练 Feign，最后停服务练熔断。

## 九、安全说明

- 代码中不包含任何真实凭据：数据库密码、管理员密码、支付宝密钥全部通过环境变量注入。
- 本地开发如需覆盖配置，请使用 `application-local.yml` 或 `.env`（**均已被 `.gitignore` 忽略**），切勿直接改受控的 `application.yml`。
- 重要提醒：一旦密钥被误提交到公开仓库，正确做法是先到平台**轮换/作废**密钥，而不是单纯删除提交——Git 历史与各类抓取缓存仍会保留旧值。
- 支付回调必须做**验签 + 幂等**处理；演示环境使用的是支付宝沙箱，不产生真实资金流。

## 十、已知边界（刻意简化之处）

- 图片上传落本地磁盘，生产应替换为对象存储（OSS / COS），项目中 `FileStorageService` 已留扩展点。
- 未引入分布式事务框架（Seata），跨服务一致性靠本地事务 + 可靠消息 + 幂等兜底体现。
- 购物车结算按 B2C 自营处理，一次结算只生成一张订单；改造为 C2C 多卖家时需在 `CartService#checkout` 按卖家拆单。
- RocketMQ、Elasticsearch 为可选依赖，缺失时相关链路走降级逻辑，不影响主流程启动。
